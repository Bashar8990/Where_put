# وين حطيته؟ (Where Did I Put It?)

تطبيق شخصي بسيط وسريع يسجّل مكان الأشياء المهمة لتجدها في ثوانٍ عندما تحتاجها.
كل البيانات تبقى على جهازك فقط — لا خوادم، لا حسابات، لا إنترنت بعد أول تحميل.

> اكتب اسم الشيء ← اعرف مكانه فورًا.

---

## الفكرة

المستخدم يضع أشياء مهمة في أماكن مختلفة (جواز السفر، المفتاح الاحتياطي، ضمان جهاز، USB…)
وينسى أين وضعها. هذا التطبيق يخزّن "الغرض ← المكان" محليًا، ويبحث عنه فورًا.

ليس نظام إدارة مخزون. ليس ERP. مجرد ذاكرة شخصية للأشياء وأماكنها.

## قاعدة البيانات (IndexedDB)

تُدار عبر Dexie.js باسم `where-did-i-put-it` (الإصدار 1).

| الجدول | المفتاح | الحقول المفهرسة |
| --- | --- | --- |
| `items` | `id` (UUID) | `searchText`, `isFavorite`, `category`, `updatedAt`, `deletedAt` |
| `images` | `id` (UUID) | — |
| `settings` | `id` (دائمًا `'app'`) | — |

- الصور تُحفظ كـ **Blob** داخل IndexedDB (وليس Base64) لتجنب تضخيم JSON.
- `searchText` عمود مُسبق الصياغة يحوي نصًا مُطبّعًا (normalized) من الاسم + المكان + الملاحظات + التصنيف، لتسريع البحث.
- `deletedAt` يدعم الحذف الناعم (Soft Delete) مع إمكانية التراجع خلال نافذة زمنية قصيرة قبل الحذف النهائي.
- `locationHistory` مصفوفة داخل العنصر تسجّل الأماكن السابقة عند كل نقل.

### Migrations
رقم إصدار الـschema معرّف في `db/database.ts`. يمكن إضافة `db.version(2).stores(...).upgrade(...)` عند الحاجة مستقبلًا.

## تخزين الصور

1. تُقرأ الصورة محليًا من `File`/`input`.
2. تُرسم على `Canvas` مع تصغير الأبعاد (الحد الأقصى 1600px).
3. تُضغط بصيغة **WebP** (إن دعم المتصفح) وإلا JPEG، بجودة 0.82.
4. تُحفظ النسخة المضغوطة كـ Blob في IndexedDB.
5. لا تُرفع الصورة إلى أي خادم.
6. عند العرض تُستخدم `URL.createObjectURL` وتُحرَّر عبر `revokeObjectURL` لتفادي تسرب الذاكرة.
7. الصور تُحمَّل بـ `loading="lazy"` ولا تُفكّ Blobs كبيرة في قائمة النتائج دفعة واحدة.

## النسخ الاحتياطي والاستعادة (Backup / Restore)

### التصدير
- يُنشئ ملف ZIP باسم `where-did-i-put-it-backup-YYYY-MM-DD.zip`.
- يحتوي:
  - `manifest.json` — `{ app, schemaVersion, createdAt, itemCount, imageCount }`
  - `items.json` — كل الأغراض + سجل الأماكن
  - `settings.json` — إعدادات التطبيق
  - `images/<id>.<ext>` — ملفات الصور
  - `images/index.json` — metadata للصور
- يتم داخل المتصفح بالكامل عبر JSZip (يُحمَّل ديناميكيًا فقط عند الحاجة).

### الاستعادة
- يُقرأ الملف محليًا ويُتحقق منه عبر **Zod schemas** قبل لمس قاعدة البيانات.
- يُعرض ملخص (عدد الأغراض/الصور/تاريخ النسخة) قبل التأكيد.
- وضعان:
  - **دمج (Merge):** للعنصر بنفس ID يُحتفظ بالأحدث حسب `updatedAt`. للصور upsert حسب ID.
  - **استبدال (Replace):** يُتحقق من الملف بالكامل أولًا، ثم يمسح ويكتب ضمن transaction واحدة.
- يُرفض الملف التالف أو بإصدار schema غير مدعوم برسالة عربية واضحة.
- `schemaVersion` يدعم migrations مستقبلية.

## PWA والعمل بدون إنترنت

- **Manifest**: اسم "وين حطيته؟"، short name "وين؟"، `display: standalone`، RTL، أيقونات 192/512/maskable.
- **Service Worker**: عبر `vite-plugin-pwa` (Workbox) — يخزّن ملفات التطبيق فقط (App Shell)، **لا** يخزن بيانات المستخدم أو الصور. البيانات في IndexedDB.
- **Offline**: بعد أول تحميل تعمل كل الوظائف الأساسية بدون اتصال (بحث، إضافة، تعديل، حذف، نقل، مفضلة، أماكن، نسخ احتياطي، استعادة).
- **التحديثات**: عند توفر إصدار جديد يظهر Toast "يتوفر تحديث جديد للتطبيق" مع زر تحديث.
- **التثبيت**: دعوة تثبيت غير مزعجة تظهر بعد إضافة أول غرض (مع إمكانية التأجيل).

### النشر (Static Hosting)
يستخدم المشروع **HashRouter** ليعمل routing على أي استضافة ثابتة بدون إعداد SPA fallback:
- GitHub Pages: انسخ محتويات `dist/` إلى فرع `gh-pages`.
- Cloudflare Pages / Netlify: أمر البناء `npm run build`، مجلد النشر `dist`.

> ملاحظة: عند النشر على مسار فرعي (مثل GitHub Pages project page) قد تحتاج لضبط `base` في `vite.config.ts`.

- جميع البيانات (أغراض، أماكن، صور) محفوظة **محليًا** على جهاز المستخدم فقط.

- التطبيق يعمل بالكامل offline بعد أول تحميل.

### تحذيرات مهمة
- **حذف بيانات الموقع/التطبيق من المتصفح قد يؤدي إلى فقدان جميع البيانات.**
- حدود تخزين المتصفح محدودة (يُعرض تقدير المساحة في الإعدادات عبر `navigator.storage.estimate()`).
- يُطلب **Persistent Storage** (`navigator.storage.persist()`) عند الحاجة لتحسين فرص احتفاظ المتصفح بالبيانات — لكنه ليس مضمونًا.
- **ننصح بأخذ نسخة احتياطية دوريًا** من صفحة الإعدادات.

## البحث العربي

`normalizeArabicText()` يطبّع النص للبحث دون تغيير النص الأصلي:
- إزالة التشكيل (tashkeel)
- توحيد ألفات: أ إ آ ٱ → ا
- توحيد الياء: ى → ي
- ة → ه
- إزالة التطويل (ـ)
- lowercase للإنجليزية
- إزالة علامات الترقيم وتطبيع المسافات

`buildSearchText()` يبني حقل `searchText` من الاسم + المكان + الملاحظات + التصنيف (عربي + مفتاح).

ترتيب النتائج: تطابق الاسم الكامل ← بداية الاسم ← احتواء الاسم ← المكان ← الملاحظات ← التصنيف، ثم تعزيز بآخر تحديث.

## الاختبارات

تُشغَّل عبر `npm run test` (Vitest + fake-indexeddb):

- **normalizeArabicText**: توحيد الألف/الياء/التاء المربوطة، إزالة التشكيل/التطويل، lowercase.
- **buildSearchText**: دمج الحقول.
- **dates**: التواريخ النسبية (اليوم/أمس/منذ X أيام) والتاريخ الكامل.
- **itemService**: إنشاء/تعديل/نقل/مفضلة/حذف ناعم/استعادة + سجل الأماكن.
- **searchService**: بحث بالاسم/المكان/الملاحظات/التصنيف، ترتيب النتائج، تطبيع عربي، فلاتر (مفضلة/تصنيف/بدون صورة)، recentItems، itemsAtLocation.
- **backupService**: تصدير/استيراد round-trip، رفض ملف غير ZIP، رفض schema غير مدعوم، رفض manifest مفقود، merge (يُبقي الأحدث)، replace، wipeAllData.

1. أضف "جواز السفر" في "درج المكتب - الرف الثاني" بملاحظة "داخل الملف الأزرق" وتصنيف "مستندات"، ثم ابحث عن "جواز" → تظهر النتيجة.

7. افصل الإنترنت بعد أول تحميل → تعمل الوظائف الأساسية.

## القيود المعروفة

- **Persistent Storage** غير مضمون: المتصفح قد يرفض الطلب أو يُخلّي البيانات تحت ضغط مساحة شديد. النسخ الاحتياطي هو الضمان الحقيقي.
- **حجم التخزين** محدود بسياسات المتصفح (يُعرض التقدير في الإعدادات).
- **إذن الكاميرا** قد يُرفض — لا يُمنع المستخدم من الحفظ بدون صورة.
- **WebP** يعتمد على دعم المتصفح (يُستخدم JPEG كاحتياطي).
- **HashRouter** يُنتج روابط بـ `#` — مقصود لضمان عمل routing على الاستضافة الثابتة بدون إعداد.
